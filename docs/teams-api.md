# Команды: контракт для бэкенда

Веб-панель уже работает с командами на имитации API (`frontend/src/mocks`). Этот документ описывает, что
должен повторить бэкенд. Эталон поведения — `frontend/src/mocks/handlers.ts`, а проверки —
`frontend/src/mocks/handlers.test.ts` (те же случаи стоит перенести в pytest).

## Модель

Администратор по-прежнему один, из `.env`. Команд может быть несколько. Каждый пользователь состоит ровно в одной
команде и видит только её платежи и общие платежи.

| Таблица | Изменение |
|---|---|
| `teams` (новая) | `id` uuid, `name` varchar(100) — уникально без учёта регистра, `telegram_chat_id` varchar null, `created_at` |
| `users` | `team_id` FK → `teams`, null только у администратора: `CHECK (role = 'admin') = (team_id IS NULL)` |
| `recurring_payments` | `team_id` FK null; **null — общий платёж для всех команд** |
| `payment_occurrences` | `team_id` FK NOT NULL; уникальность `(recurring_payment_id, team_id, seq)` вместо `(recurring_payment_id, seq)` |
| `budgets` | `team_id` FK NOT NULL; уникальность `(team_id, currency, period_type, year, month)` |

Миграция `0003`: создать команду (например, «Основная команда»), перенести в неё всех пользователей с `role = user`,
все периоды и бюджеты. Существующие платежи оставить общими (`team_id = null`), тогда для одной команды всё работает
как раньше.

Статусы, просрочка и защита от дублей напоминаний (`UNIQUE(occurrence_id, channel, kind)`) не меняются: у каждой
команды свой период, а значит своя отметка и своё напоминание.

## Периоды

- Платёж команды создаёт периоды только у неё.
- Общий платёж создаёт периоды у **каждой** команды с теми же сроками и тем же `seq`. Оплата одной команды не
  меняет период другой.
- **Команда, созданная позже платежа**, получает его со дня своего создания: пропускаются сроки раньше
  `teams.created_at` (дата в `APP_TIMEZONE`). Так у новой команды нет долгов за прошлое. Иначе `missing_occurrences`
  начнёт с `seq = 0`, и все прошлые сроки сразу станут просроченными.
- Новая команда получает общие платежи сразу при `POST /teams` (вызвать `ensure_occurrences`), а не только при следующем
  запуске worker.
- Прекращение платежа (`DELETE /recurring-payments/{id}`) действует на все команды.
- Плановые даты (календарь и итоги) у общего платежа считаются по каждой команде.

## Доступ

- **Пользователь** видит периоды только своей команды, платежи своей команды и общие. Параметр `team_id` для него
  необязателен. Если передан `team_id` чужой команды, ответ **403** `forbidden`.
- Конкретный период, платёж или вложение чужой команды для пользователя возвращает **404** `not_found`, а не 403,
  чтобы не раскрывать, что такой объект есть. Это касается `GET`/`PATCH /payment-occurrences/{id}`, вложений,
  скачивания и `GET /recurring-payments/{id}`.
- **Администратор** видит всё. Необязательный `team_id` сужает списки до команды; для платежей это платежи
  команды и общие. Неизвестный `team_id` возвращает 404. Конкретный платёж или период администратор открывает
  при любом `team_id`, например по ссылке из журнала. В `GET /recurring-payments/{id}` у платежа команды `occurrences`
  всегда содержит её периоды, а у общего платежа — периоды по `team_id`.

## API

Пути и поведение обязательных эндпоинтов кейса не меняются. Новые поля обязательны в ответах, их проверяет
`backend/tests/contract/test_frontend_contract.py` по `frontend/src/api/types.ts`.

### Новые эндпоинты (только администратор)

| Метод | Путь | Тело / ответ |
|---|---|---|
| GET | `/api/v1/teams` | `Page<Team>`, по имени |
| POST | `/api/v1/teams` | `{name, telegram_chat_id}` → 201 `Team` |
| PATCH | `/api/v1/teams/{id}` | любые из `{name, telegram_chat_id}` → `Team` |
| DELETE | `/api/v1/teams/{id}` | 204; **409 `team_not_empty`**, если в команде есть участники, свои платежи, оплаченные периоды или вложения |

`Team = {id, name, telegram_chat_id, members_count, created_at}`.
Ошибки: имя занято → **409 `team_name_taken`**; пустое имя или длиннее 100 символов → 422.
`telegram_chat_id` — число (`-1001234567890`) или `@имя_канала`, иначе 422; пустое значение — null.
В журнал пишутся действия `team.create`, `team.update`, `team.delete` с `details.name`.

### Изменённые ответы

| Схема | Новое поле |
|---|---|
| `User` (и `me.user`, ответ входа) | `team: {id, name} \| null` |
| `RecurringPayment` | `team: {id, name} \| null` (null — общий) |
| `Occurrence` | `team: {id, name}` |
| `PlannedItem` | `team: {id, name}` |
| `InboxItem` | `team: {id, name}` |
| `NotificationLog` | `team: {id, name} \| null` |
| `Budget` | `team_id` |

`RecurringPayment.next_occurrence` — ближайший период в выбранной команде. Для общего платежа в режиме «все
команды» это самый ранний неоплаченный период среди команд.
`GET /recurring-payments/{id}` → `occurrences`: периоды выбранной команды или всех команд, сортировка по сроку
(новые сверху), затем по названию команды.

### Изменённые запросы

| Эндпоинт | Изменение |
|---|---|
| `POST /recurring-payments` | `team_id`: id команды или null. **Не передан — общий платёж** (так старые клиенты и тесты кейса работают как раньше). Неизвестная команда → 422 |
| `GET /recurring-payments`, `GET /recurring-payments/{id}`, `GET /payment-occurrences`, `GET /payments/summary`, `GET /payments/calendar`, `GET /budgets`, `GET /users` | необязательный `team_id` (см. «Доступ») |
| `POST /users` | `team_id` обязателен → иначе 422 |
| `PATCH /users/{id}` | `team_id` необязателен; перевод в другую команду не трогает прошлые отметки |
| `PUT /budgets` | у каждого элемента `team_id` существующей команды → иначе 422 |

Итоги (`/payments/summary`) для всех команд — сумма итогов команд. `budget` — сумма бюджетов команд, если они заданы.

## Напоминания

- **Telegram**: в `teams.telegram_chat_id` команды периода; если он пуст, в `TELEGRAM_CHAT_ID` из `.env`.
- **Почта**: только участникам команды периода с `notify_email`.
- **Webhook**: общий, в данные добавить `team: {id, name}`.
- **Колокольчик** (`/inbox`, `/inbox/read-all`): пользователь видит уведомления только своей команды, администратор —
  всех.
- **Кнопка «Оплачено» в Telegram**: отметить может участник команды периода или администратор. Остальным бот
  отвечает, что период другой команды.
