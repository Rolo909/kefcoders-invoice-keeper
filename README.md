# Invoice Keeper — напоминания о регулярных платежах

Система, которая не даёт забыть об аренде, подписках и оплате серверов.
Администратор вносит регулярные платежи, бот за 3 дня до срока пишет в Telegram-чат,
команда отмечает оплату в веб-панели и видит, что и когда оплатить, что оплачено и что просрочено.

- Веб-панель: **http://localhost:8080**
- Swagger: **http://localhost:8080/api/v1/docs**
- OpenAPI-спецификация: [`docs/openapi.yaml`](docs/openapi.yaml)
- Сценарий защиты: [`docs/demo-scenario.md`](docs/demo-scenario.md)

## Быстрый старт

Нужен только **Docker** с Compose v2 (Docker Desktop на Windows/macOS или Docker Engine на Linux).

```bash
git clone https://github.com/Rolo909/kefcoders-invoice-keeper.git
cd kefcoders-invoice-keeper
cp .env.example .env
```

Откройте `.env` и задайте:

| Переменная | Что указать |
|---|---|
| `ADMIN_PASSWORD` | пароль администратора, не короче 8 символов |
| `POSTGRES_PASSWORD` | любой пароль для базы данных |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | бот и чат для напоминаний — как получить, см. ниже |

```bash
docker compose up --build -d
```

Первый запуск занимает несколько минут: собираются образы. Когда команда завершится, откройте
http://localhost:8080 и войдите администратором: логин `admin` (`ADMIN_LOGIN`), пароль — из `ADMIN_PASSWORD`.

Проверить, что всё поднялось:

```bash
docker compose ps
```

У `db` и `backend` должен быть статус `healthy`, у `worker` и `frontend` — `running`.

Остановить: `docker compose down`. Данные хранятся в Docker-томе и переживают перезапуск.
Начать с чистой базы: `docker compose down -v`, затем снова `docker compose up -d`.

### Telegram: бот и чат

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, придумайте имя — он пришлёт токен
   вида `123456789:AA…`. Это `TELEGRAM_BOT_TOKEN`.
2. Добавьте бота в групповой чат команды (или просто напишите боту `/start` в личке).
3. Отправьте в этот чат любое сообщение и откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — в ответе найдите `"chat":{"id":…}`.
   Это `TELEGRAM_CHAT_ID`; у групп он отрицательный, например `-1001234567890`.
4. Впишите оба значения в `.env` и перезапустите: `docker compose up -d`.

Без токена система работает полностью, только напоминания не уходят: в истории периода видна причина
«Telegram не настроен». Как только токен появится, ближайшая проверка (раз в минуту) отправит их.

## Учётные записи и тестовые данные

При первом запуске (`SEED_DEMO_DATA=true`) создаются тестовые данные — даты считаются от сегодняшнего дня,
поэтому сценарий защиты работает в любой день.

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | из `ADMIN_PASSWORD` в `.env` | администратор (задаётся только в `.env`) |
| `anna` | `anna12345` | пользователь |
| `maria` | `maria12345` | пользователь |
| `user` | `user12345` | пользователь |

13 регулярных платежей в трёх валютах, среди них:

| Платёж | Валюта | Что показывает |
|---|---|---|
| Аренда офиса | RUB | срок через 2 дня — напоминание уходит сразу после запуска |
| Бухгалтерское сопровождение | RUB | срок завтра |
| Сервер DigitalOcean | USD | текущий период просрочен, прошлые оплачены вовремя |
| Figma Professional | EUR | оплата 31-го: в коротких месяцах срок — последний день; один период оплачен с опозданием |
| Страхование офиса | RUB | ежеквартальный платёж |
| Домен invoicekeeper.ru | RUB | ежегодный платёж |
| Хостинг Timeweb | RUB | прекращённый платёж: история оплат сохранена, напоминаний нет |

Бюджеты по каждой валюте на текущий месяц и год тоже заданы. Тестовые данные создаются один раз;
чтобы получить пустую систему, поставьте `SEED_DEMO_DATA=false` и начните с чистой базы.

## Как это работает

| Требование кейса | Как сделано |
|---|---|
| Каждый период — своя дата и отметка «Оплачено / Не оплачено» | Таблица периодов: у каждого срока своя запись со статусом и фактической датой. Новые периоды создаются по расписанию и не зависят от оплаты прошлых — просрочка не останавливает следующие периоды, история не стирается |
| Нет такого числа в месяце → последний день | Срок периода считается от первой даты платежа, а не от предыдущего срока: 31.01 → 28.02 → 31.03, а не «застревает» на 28-м |
| Просрочка — со следующего дня после срока | Просрочка не хранится, а вычисляется из срока и фактической даты оплаты. Поэтому исправление даты сразу убирает ошибочную просрочку, а срок не меняется |
| Отмена отметки очищает дату | Ограничение в базе данных: «оплачено» ⇔ указана фактическая дата |
| Напоминание минимум за 3 дня, без дублей | Отдельный процесс `worker` раз в минуту проверяет сроки. Каждое напоминание записывается в журнал с уникальным ключом (период, канал, тип) — повторная или одновременная проверка второе сообщение не отправит |
| Оплаченный период и удалённый платёж не напоминают | Условия проверяются в момент отправки |
| Платёж добавили позже, чем за 3 дня до срока | Напоминание отправляется сразу после создания, не дожидаясь проверки |
| Удаление платежа | «Прекращение»: прошлые и оплаченные периоды остаются в истории, будущие неоплаченные удаляются вместе с напоминаниями |
| Единый часовой пояс | `APP_TIMEZONE` из `.env`; «сегодня» везде считается в нём, а не по часам контейнера |
| Две роли, ограничения и в панели, и в API | Все маршруты API, кроме входа, требуют авторизации; действия администратора проверяются на сервере. Администратор задаётся только в `.env` и через API не меняется |
| RUB, USD, EUR — итоги отдельно | Суммы в `Decimal`, итоги одним SQL-запросом с группировкой по валюте, без конвертации |
| Всё сохраняется после перезапуска | PostgreSQL в Docker-томе, миграции Alembic применяются при старте |

Сервисы `docker compose`:

| Сервис | Назначение |
|---|---|
| `frontend` | веб-панель (React), nginx на порту 8080 проксирует `/api/` в backend |
| `backend` | API на FastAPI; при старте применяет миграции, синхронизирует администратора из `.env` и создаёт тестовые данные |
| `worker` | проверяет сроки и отправляет напоминания |
| `db` | PostgreSQL 16 |

Стек: Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16, APScheduler, Telegram Bot API;
React 18, TypeScript, Vite, Mantine, TanStack Query. Подробный план и решения — [`TASK_PLAN.md`](TASK_PLAN.md).

## API

Все эндпоинты — с префиксом `/api/v1`. Документация с возможностью отправлять запросы — Swagger
на http://localhost:8080/api/v1/docs: выполните `POST /auth/login`, скопируйте `access_token` и нажмите
**Authorize**. Ошибки всегда приходят в виде `{"detail": "текст для пользователя", "code": "машинный код"}`.

| Метод | Эндпоинт | Назначение | Кто может |
|---|---|---|---|
| POST | `/auth/login` | вход по логину и паролю | все |
| GET | `/auth/me` | текущий пользователь | вошедшие |
| POST | `/auth/logout` | завершение текущей сессии | вошедшие |
| GET | `/recurring-payments` | список регулярных платежей | вошедшие |
| POST | `/recurring-payments` | создание регулярного платежа | администратор |
| DELETE | `/recurring-payments/{id}` | прекращение платежа и напоминаний с сохранением истории | администратор |
| GET | `/payment-occurrences` | список периодов; фильтры по статусу, просрочке, датам, валютам | вошедшие |
| GET | `/payment-occurrences/{id}` | конкретный период с историей изменений и напоминаниями | вошедшие |
| PATCH | `/payment-occurrences/{id}` | отметить или отменить оплату, исправить фактическую дату | вошедшие |
| GET | `/payments/summary` | итоговые суммы по валютам | вошедшие |
| GET | `/users` | список пользователей | администратор |
| POST | `/users` | создание обычного пользователя | администратор |
| PATCH | `/users/{id}` | изменение пользователя | администратор |
| DELETE | `/users/{id}` | удаление пользователя | администратор |
| GET | `/docs` | Swagger-документация | все |

Дополнительно: `GET /recurring-payments/{id}` (платёж со всеми периодами), `PATCH /auth/me` (своя почта),
`GET /health`. Полная спецификация — [`docs/openapi.yaml`](docs/openapi.yaml).

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_TIMEZONE` | `Europe/Moscow` | единый часовой пояс для сроков и просрочки |
| `REMIND_DAYS_BEFORE` | `3` | за сколько дней до срока напоминать (не меньше 3) |
| `REMINDER_CHECK_INTERVAL_MINUTES` | `1` | как часто worker проверяет сроки |
| `OCCURRENCE_HORIZON_DAYS` | `60` | на сколько дней вперёд создаются периоды (всегда есть хотя бы один будущий) |
| `SESSION_TTL_HOURS` | `168` | срок жизни сессии без активности |
| `SEED_DEMO_DATA` | `true` | создать тестовые данные при первом запуске |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | `admin`, — | единственный способ задать администратора |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | — | база данных |
| `TELEGRAM_ENABLED`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | `true`, —, — | напоминания в Telegram |

Остальные переменные в `.env.example` относятся к дополнительным каналам и вложениям.

## Если что-то не работает

| Симптом | Что сделать |
|---|---|
| Порт 8080, 8000 или 5432 занят | Остановите программу, которая его занимает, или поменяйте левую часть `ports` в `docker-compose.yml` |
| `backend` не становится `healthy` | `docker compose logs backend` — чаще всего `ADMIN_PASSWORD` короче 8 символов или не задан `POSTGRES_PASSWORD` |
| Напоминания не приходят в Telegram | Откройте период → «Напоминания»: там видна причина. Проверьте токен и `chat_id`, бот должен быть участником чата. Логи: `docker compose logs worker` |
| Поменяли `.env`, а изменений нет | `docker compose up -d` — сервисы перечитают `.env` |
| Нужна чистая база | `docker compose down -v`, затем `docker compose up -d` |

## Разработка

Тесты бэкенда (нужен Python 3.12+ и запущенная база):

```bash
docker compose up -d db
cd backend
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pytest
```

На Windows вместо `.venv/bin/` — `.venv\Scripts\`. Тесты работают в отдельной базе `invoice_keeper_test`
и рабочие данные не трогают. Проверки стиля и типов: `ruff check .`, `ruff format --check .`, `mypy app tests`.

После изменения API обновите спецификацию — тест следит, чтобы файл не отставал от кода:

```bash
cd backend
.venv/bin/python -m app.scripts.export_openapi
```

Веб-панель без бэкенда, на имитации API — см. [`frontend/README.md`](frontend/README.md).

## Структура репозитория

```
backend/            API, worker, миграции, тесты (Python)
  app/domain/       расчёт сроков и просрочки — без зависимостей от фреймворков
  app/services/     бизнес-логика: платежи, периоды, напоминания, итоги, пользователи
  app/api/v1/       HTTP-эндпоинты
  alembic/          миграции базы данных
frontend/           веб-панель (React)
docs/               openapi.yaml, сценарий защиты
docker-compose.yml  запуск всего одной командой
```
